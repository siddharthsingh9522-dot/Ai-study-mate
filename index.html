Settings / user supplied keys

Your keys, your control.

This standalone file does not contain an API key. Enter your own key in the browser when you want to use a provider.

Important: browser-side keys can be inspected by the page and network tools. Use a key with billing limits/restrictions, never a production master key, and clear it after use on a shared device. Wikipedia’s summary endpoint is public and needs no key.

Auto-switch: if the selected model hits a limit or error, Study Mate tries the other Gemini models, then Groq models. Audio, guard and safeguard models are left out because they cannot write study answers.

Deep audit / original source

What was fixed.

This is the practical audit of the uploaded project snapshot and the design decisions behind this standalone build.

Original project findings

  • Split architecture: the repository contains a React mockup and a separate legacy `public/` app. The Express server serves `public/`, so the polished React screen was not the actual production flow.
  • Dead Topic Explorer: the React UI sends `topic`, `topicLevel`, and `topicFocus`, but the server’s generation switch has no `topic` mode and returns “Invalid mode.”
  • Provider lock-in: the backend initializes one server-side Gemini client and one fixed model. No Groq fallback, no public Wikipedia enrichment, and no user-entered provider key existed.
  • Fragile structured output: AI JSON was parsed in the browser with no schema validation or retry/repair pass. A malformed response becomes a generic “could not be read” screen.
  • Operational risk: no visible request budget/rate limit, no source-page citations, and the client can resend a large chat history. Gemini file uploads are temporary and are not explicitly deleted.
  • Security trade-off: the original server-side key model is safer for a hosted app. This standalone version intentionally trades that for user-controlled browser keys, with a warning and no embedded secret.

Standalone improvements

  • Local-first PDF handling: browser extracts page text and adds page markers before any AI call; the PDF file itself is not uploaded by this HTML.
  • Automatic failover: Gemini is attempted first when a Gemini key exists; any network/API/model error moves the same request to Groq when a Groq key exists.
  • Useful without a PDF: Topic Explorer requests the public Wikipedia summary endpoint and passes that context to the selected AI provider.
  • Safer rendering: model text is escaped before insertion into the page; generated JSON has a loose parser plus a readable fallback instead of raw HTML injection.
  • Small, portable surface: one HTML file, no Node server, login, database, `.env`, or upload directory required. CDN access is needed for PDF.js.

Local-first upgrade

  • Offline persistence: PDF text and metadata live in IndexedDB; chat, last results, theme, flashcard progress and API settings live in localStorage. Every storage call is wrapped so a blocked or full browser store never breaks the app.
  • Multi-model auto-switch: if the chosen model hits a quota, rate limit or outage, the next Gemini model is tried, then the Groq models. Dead models are remembered briefly so later requests skip them.
  • Key diagnostics: “Test both keys” checks Gemini and Groq separately; “Test every model” shows which individual models work right now.
  • Ask Doubt without a PDF: the tutor now works like a general assistant, using PDFs and Wikipedia only when they help.
  • Study comfort: audio tutor, Light / Dark / Sepia themes, Zen reading mode, spaced-repetition flashcards with a saved Hard list, PDF export and image OCR.
  • Fixed: Groq list no longer contains audio/guard models or labels like “(deprecated)” that were sent as invalid model ids; the Gemma entry now uses real model ids; the Gemini key travels in a header instead of the URL; custom model names and the “remember keys” checkbox now survive a reload.
